Findings

01AGENTS.md / CLAUDE.md💀 Broken
Neither AGENTS.md nor CLAUDE.md exists at the repo root. The only orientation an agent gets is README.md + DESIGN.md — both written for humans.
Fix: create AGENTS.md at the root with: stack & entrypoints (paperclaw classify | ask | mcp), the four npm verbs, where transcripts/log live, and one paragraph on how to dogfood the MCP server.
02Strict type/compiler settings🩹 Patchy
tsconfig.json enables strictNullChecks and noImplicitAny individually but does not set "strict": true, noUncheckedIndexedAccess, or exactOptionalPropertyTypes. Half of strict mode is off.
Fix: replace the granular flags with "strict": true, "noUncheckedIndexedAccess": true, "exactOptionalPropertyTypes": true in tsconfig.json and fix the fallout once.
03Strict linter / formatter🩹 Patchy
.eslintrc.js extends only @typescript-eslint/recommended + plugin:prettier/recommended and explicitly disables no-explicit-any, explicit-function-return-type, and explicit-module-boundary-types. lint:check does not pass --max-warnings 0. Prettier is wired correctly.
Fix: extend plugin:@typescript-eslint/strict-type-checked + stylistic-type-checked, drop the no-explicit-any: off override, and change the script to eslint ... --max-warnings 0.
04Schema validation at boundaries🚀 Ship-Ready
src/mcp/mcp.service.ts imports zod and defines a Zod schema for every MCP tool input: z.enum(CATEGORIES) for category, z.string().regex(...) for ISO dates, bounded z.number().int().min().max() for limit, and each field is .describe()'d so the agent gets self-documenting tools. The classifier output is similarly constrained to a closed category list.
05Business logic separated from I/O👍 Solid
src/library/front-matter.util.ts, src/library/transcript.util.ts, and src/search/search.service.ts are pure or near-pure and each has a sibling .spec.ts that exercises logic without touching disk or network. NestJS dependency injection means I/O services (library.service.ts, log.service.ts) can be substituted in tests.
06One-command bring-up🩹 Patchy
README requires the dance npm install → cp .env.example .env → edit key → npm run build → npm link. There is no single check (typecheck + lint + test) script and no setup verb in package.json.
Fix: add "check": "npm run typecheck && npm run lint:check && npm run format:check && npm test" and a setup script that copies .env.example if missing — collapse the README to npm run setup && npm run build.
07Pre-commit feedback loop🩹 Patchy
.husky/pre-commit runs npx lint-staged + npm run typecheck. No secret scanning (no gitleaks, no .gitleaksignore), no test run on changed files, and the hook only fires after npm install triggers husky's prepare — a fresh clone could commit anything until install runs.
Fix: add gitleaks protect --staged --redact as the first hook line and npx jest --bail --findRelatedTests $(git diff --cached --name-only --diff-filter=ACMR) as the last.
08Dead-code guardrail💀 Broken
No knip, ts-prune, or equivalent in devDependencies or scripts. ESLint config does not enable import/no-unused-modules. Nothing flags unused exports in src/.
Fix: npm i -D knip, add knip.json with the NestJS entrypoint preset, and append npx knip --no-exit-code (or stricter) to the check script.
09Logs reachable from terminal🚀 Ship-Ready
NestJS logger streams events to stdout, and every classify run also appends to library/processing.log as JSON Lines (start / processed / skipped / error). README documents both. Trivially tail -f-able from the agent's shell.
10Docs stay in sync with code💀 Broken
README.md and DESIGN.md document the MCP tool table by hand. Nothing — no pre-commit hook, no CI rule, no codegen — checks that they match what src/mcp/mcp.service.ts actually registers. The tool tables will drift on the next refactor.
Fix: generate the README's tool table from the registered MCP tool list at build time (a small script that reads the registry and writes between <!-- mcp:start --> markers), and add a lefthook check that fails if source changes don't touch any *.md.
11Agent can self-test changes end-to-end👍 Solid
Three real exercise paths: paperclaw classify (CLI, stdout output), paperclaw ask "<q>" (streams Claude's answer), and paperclaw mcp (stdio MCP server auto-loaded via .mcp.json). Output is captured-to-stdout / JSONL — an agent can read what happened. The discovery story is README-only; without AGENTS.md an agent has to skim through prose to find this.
12Agentic review panel💀 Broken
No REVIEW.md, no /review slash command in .claude/, no script or CI workflow that spawns parallel specialist reviewers. Human is the first (and only) reviewer of every diff.
Fix: add a .claude/commands/review.md that fans out to security / TypeScript-strictness / DRY / Nest-architecture reviewers, plus a short REVIEW.md listing what NOT to flag (any-existing-code suggestions, "consider library X", theoretical risks).
13Friction proportional to blast radius💀 Broken
src/library/library.service.ts moves files on the user's filesystem and writes to library/processing.log — both irreversible-ish surfaces — yet no CODEOWNERS, danger-zone hook, or printed checklist gates edits to those files. There is no named bypass either, because there is no friction to bypass.
Fix: add a lefthook.yml pre-push step that grep's for changes to src/library/** or src/classify/categories.ts and prints "you're touching the filesystem move path / closed category list — run npm run check and add a spec. Bypass with PAPERCLAW_DANGER_OK=1."
14Tooling tuned for the agent🩹 Patchy
No .gitleaksignore exists (no gitleaks either — see item 7). The husky pre-commit just runs lint-staged + typecheck; on failure the agent gets raw tool output, no "run npm run lint to fix" remediation hint. Lint suppressions are blanket (no-explicit-any: off) rather than per-line with a justification.
Fix: wrap the husky hook so failures print "❌ pre-commit failed → run: npm run lint && npm run format", and replace the blanket ESLint disables with file-local // eslint-disable-next-line ... -- reason.

🎁 Bonus finds

  • Project-scoped .mcp.json dogfooding its own server — Claude Code launched from the repo root automatically picks up paperclaw mcp as a tool source, so the agent searches its own classified library through the same interface a human gets. Self-hosting feedback loop.
  • Closed category enum shared between classifier & MCP boundary — src/classify/categories.ts exports one tuple consumed by both the Anthropic classification prompt and the Zod z.enum(CATEGORIES) on search_transcripts. The model physically cannot invent a one-off folder; the directory tree stays predictable across agent runs.
